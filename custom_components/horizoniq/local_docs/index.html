HorizonIQ

Local documentation served from your Home Assistant instance.

This integration polls your HorizonIQ forecast API, exposes forecast entities in Home Assistant, and caches tokens needed for efficient polling.

Configuration Fields

FieldRequiredDescription

api_keyYesAPI key sent in request header X-API-KEY.

hashNoDeterministic result of the most recent forecast, sent as the hash query value.
registration_dataNoRegistration data for your site. Sent as registrationData so it is not constantly reloaded from the database. Refreshes daily or when force-refreshed with the clear registration button.
forecast_device_idNoCanonical device ID for app-owned trial binding, sent as X-HorizonIQ-Device-Id when set. Victron/Home Assistant setups usually use the GX device ID.
forecast_device_tokenNoPortal-generated app trial device token, sent as X-HorizonIQ-Device-Token when set.

Entities

Binary Sensors

  • HorizonIQ Import
  • HorizonIQ Export

Export is on only when the current schema-5 period explicitly selects export_for_profit with import-for-export enabled. Live and Virtual use recommendedAction; Replay uses simulationAction. Advisory plans and solar-headroom export do not turn it on. Its attributes expose only the plan/action source, selected action, expected export kWh, and executable status.

Sensors

  • HorizonIQ Total Cost
  • HorizonIQ Charging Cost
  • HorizonIQ Saving
  • HorizonIQ Forecast Diagnostics
  • HorizonIQ BMS State
  • HorizonIQ Trial Status

Button

  • HorizonIQ Clear Registration clears cached registration_data and triggers a refresh.

Stored Client-Side Data

Persisted in Home Assistant config entries:

  • url
  • api_key
  • battery_capacity_sensor
  • environment
  • hash
  • registration_data
  • forecast_device_id
  • forecast_device_token

The read-only Home Assistant Installation ID is read from Home Assistant core.uuid storage and displayed only as metadata.

Runtime-only values (not persisted): normalized forecast payload, periods, currency, target capacity, app trial status, authorization diagnostics, and last update status.

Request Notes

The optional app-trial headers are X-HorizonIQ-Device-Id and X-HorizonIQ-Device-Token.

If you sign in through a Test Mode portal, subscribe and repair links stay on that same portal host.

Sandbox virtual battery

Sandbox entries using Virtual battery expose one isolated device. Enable Simulation first; operational numbers, selectors, buttons, and telemetry are unavailable while it is disabled. Each entry has its own generated GX ID, virtual clock, profile directory, snapshots, faults, and MQTT handlers.

Use the device to change synthetic load/solar, battery limits and efficiencies, and the active-only Set state of charge slider. It accepts the configured reserve through 100%, updates stored energy immediately, and never advances the virtual clock. Use horizoniq.set_virtual_battery_state_of_charge with one active entry ID for automations; playback and replay must be stopped first.

Profiles are synthetic JSON or CSV files under <HA config>/horizoniq/profiles/<config_entry_id>/, validated at five-minute resolution and limited to 31 days. Snapshots are local and contain virtual state only; no credentials, production identities, or actual telemetry.

Energy-balance health checks: grid import + solar + battery discharge + signed manual adjustment = load + battery charge + grid export + modeled conversion losses. Manual adjustment is local simulator setup, not grid, solar, loss, saving, or actual telemetry. Conversion loss is expected when efficiency is below 100%; a balance error beyond tolerance marks the sandbox unhealthy.

MQTT setup

Configure Home Assistant MQTT with Mosquitto or another compatible broker, then create one sandbox-only Node-RED account. Where supported, limit its ACLs to victron/N/horizoniq-*, victron/W/horizoniq-*, victron/R/horizoniq-*, and horizoniq/sandbox/horizoniq-*.

Give each Node-RED sandbox runtime a unique client ID and its matching generated GX ID. Topics are created automatically—do not provision them manually. Enable a sandbox, check MQTT health, step it, validate synthetic N telemetry and a matching non-retained W acknowledgement, then use R/.../keepalive to validate refresh. Repeat with another sandbox to verify isolation.
